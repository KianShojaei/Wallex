# Wallex Agent — ایجنت معاملاتی Agentic AI برای چالش والکس

**هکاتون Agentic AI استارکوچ · چالش والکس · ۷۲ ساعت · ۵ میلیون تومان · حساب Spot اختصاصی**

> یک ایجنت خودگردان که به‌جای شکار نویز قیمت، **تنها منبع سود پایداری که داده‌ی واقعی والکس نشان می‌دهد** را می‌گیرد: ضعیف شدن تومان. رژیم ارزی را با قواعد عددی روی USDT/TMN می‌سنجد، آن را از طریق **سبد دینامیکی از حامل‌های دلاری** (طلای تتر، بیت‌کوین، اتریوم) اجرا می‌کند، اندازه‌ی هر پا را به یک **تحلیل‌گر LLM** با خروجی JSON سخت می‌سپارد، و همه چیز را زیر یک **موتور ریسک شش‌لایه** و **لاگ تصمیم دقیقه‌به‌دقیقه** نگه می‌دارد. یک هسته‌ی تصمیم برای بک‌تست، شدو و اجرای زنده؛ داشبورد لحظه‌ای؛ سرور MCP برای بازرسی با Claude.

📊 **ارائه‌ی دو اسلایدی (صورت مسئله + خلاصه‌ی گرافیکی معماری):** [`docs/presentation.html`](docs/presentation.html) · 🔬 **شواهد داده‌ای:** [`docs/research.md`](docs/research.md)

## ۱. چرا این راهکار؟ (شواهد، نه سلیقه)

۳۰ روز کندل ۱ دقیقه‌ای واقعی والکس (۲۲ سپتامبر تا ۲۲ اکتبر ۲۰۲۶، حدود ۴۳ هزار کندل در هر بازار) را با کارمزد واقعی حساب چالش (Taker ۰.۳٪) و روش Walk-forward آزمودیم:

| یافته | عدد |
|---|---|
| USDT/TMN در ۳۰ روز | **+۱۸.۴٪** (۱۹ روز از ۳۰ مثبت) |
| همه‌ی ۷ ارز بزرگ به دلار | **منفی** (BTC −۵٪ … DOGE −۲۱٪) |
| بازگشت به میانگین، ترکیب‌های مثبت خارج از نمونه | **۰ از ۶۴۸** |
| روندگرایی، ترکیب‌های مثبت خارج از نمونه (بازار دلاری، کارمزد ۰.۲۶٪) | **۰ از ۷۶۸** |
| پنجره‌های ۳ روزه‌ی مثبت برای نگهداری دارایی دلاری | **۶۰٪** (میانه +۱٪) |

نتیجه‌ی منطقی: در این بازار و با این کارمزد، **زمان‌بندی تکنیکال سودی اضافه نمی‌کند**؛ سود از اکسپوژر هوشمند به دلار می‌آید. پس استراتژی باید (۱) رژیم تومان را درست تشخیص دهد، (۲) اکسپوژر را به قدرت رژیم گره بزند، (۳) ریسک حامل‌ها را پخش و محدود کند. آزمون زنده نشان داد حساب چالش سفارش روی USDTTMN را رد می‌کند، پس حامل‌های دلاری جایگزین شدند. جزئیات کامل در `docs/research.md`.

## ۳. منطق تصمیم (هر دقیقه، روی کندل‌های بسته‌شده‌ی ۱ ساعته)

### ۳.۱ رژیم ارزی (قواعد)
| | قاعده |
|---|---|
| روشن | `close(USDTTMN) > EMA(72h)` **یا** بازده ۲۴h > +۰.۳٪ |
| خاموش | `close < EMA(72h)` **و** بازده ۲۴h < −۰.۳٪ (هیسترزیس) |
| score | ۰.۵×مومنتوم ۲۴h + ۰.۳×مومنتوم ۷۲h + ۰.۲×فاصله از EMA، منهای جریمه‌ی نوسان غیرعادی |
| کف اکسپوژر | خطی از **۸۰٪** (score ۰.۶) تا **۹۵٪** (score ۱.۰)؛ زیر ۰.۵ ورود جدید نمی‌کند |

### ۳.۲ سبد حامل‌ها
- وزن پایه: طلای تتر ۵۰٪، بیت‌کوین ۳۰٪، اتریوم ۲۰٪ از سقف سبد (۹۵٪ سرمایه).
- **وزن دینامیک:** بازده ۷۲ ساعته‌ی *دلاری* هر حامل (قیمت تومانی ÷ USDTTMN) با میانگین سبد مقایسه می‌شود؛ ضریب ۰.۵× تا ۱.۵× وزن پایه، نرمال‌شده.
- **گارد حامل:** ورود فقط اگر قیمت ≥ ۹۹.۵٪ EMA ۴۸h خودش و افت ۲۴h کمتر از ۱.۵٪؛ افت > ۳٪ = خروج اضطراری.
- **بازتوازن:** طلا (Maker ۰٪) هر ۳۰ دقیقه به وزن هدف ±۳٪؛ BTC/ETH فقط بالای ۱۱۰٪ سقف.
- افزودن ارز = دو خط در `config/settings.yaml` (`markets.allowed` و `carriers`).

### ۳.۳ نقش واقعی AI
| نقش | مدل | زمان | خروجی | اثر |
|---|---|---|---|---|
| تحلیل رژیم هر حامل | `gpt-6-sol` | هر ۶۰ دقیقه (۱۵ دقیقه وقتی مخالف است) | `regime, confidence, allow_entries, size_factor, summary` | سایز از کف تا سقف |
| قضاوت روی هر کاندید | `gpt-6-luna` | هر فرصت ورود/افزایش | `action, confidence, size_factor, stop_loss_pct, rationale, key_risks` | سایز نهایی = max(کف قواعد, min(AI, رژیم)) × ضریب نوسان |

هر ماژول یک **بریف استراتژی** به مدل می‌دهد تا کاندید را با تز خودش بسنجد. AI نمی‌تواند زیر کف قواعد برود یا بالای سقف؛ خروجی‌اش با pydantic اعتبارسنجی و در `logs/ai_cache` ذخیره می‌شود تا با `--ai replay` بایت‌به‌بایت بازپخش شود. در اجرای زنده‌ی ۲۳ اکتبر، مدل بارها به‌خاطر «ضعف طلا در برابر رشد دلار» اندازه را کم کرد و دلیلش در لاگ ثبت است.

### ۳.۴ خروج
تسویه‌ی پایان چالش → Kill switch → حد ضرر ۲.۵٪ → رژیم خاموش → سقوط حامل. سفارش‌ها اول Maker (طلا ۰٪، کریپتو ۰.۲٪)، در صورت پر نشدن Taker.

## ۴. مدیریت ریسک (`config/settings.yaml`)

| قاعده | مقدار |
|---|---|
| اکسپوژر کل | ۸۰٪ تا ۹۵٪ بر اساس قدرت رژیم؛ حداقل ۵٪ تومان |
| سقف هر حامل | وزن دینامیک × ۹۵٪ |
| حد ضرر هر پا | ۲.۵٪ (AI فقط می‌تواند تنگ‌تر کند) |
| توقف روزانه | افت ≥ ۲٪ از ابتدای روز → بدون ورود جدید |
| Kill switch | افت ≥ ۴٪ از سقف → همه به تومان، توقف |
| Cooldown | ۶ ساعت بعد از استاپ؛ افزایش حداکثر هر ۳۰ دقیقه |
| انطباق | فهرست ۳۴۵ بازار غیرفعال (`config/blocked_markets.yaml`) در بارگذاری و قبل از هر سفارش |
| تسویه | ۴۵ دقیقه قبل از پایان رسمی (دوشنبه ۲۳:۰۰ تهران → ۲۲:۱۵) |
| پایداری | reconcile با موجودی واقعی صرافی در هر شروع؛ ری‌استارت خودکار؛ وضعیت روی دیسک |

## ۵. نتایج

**بک‌تست (داده‌ی واقعی والکس، موتور واقعی، کارمزد واقعی):**

| اجرا | بازده | بیشینه افت | معاملات |
|---|---|---|---|
| هسته روی XAUTTMN، ۲۶ سپتامبر تا ۲۳ اکتبر | **+۳.۸٪** | ۲.۰٪ | ۵ (۵ برنده) |
| نیمه‌ی اول / دوم (walk-forward) | +۳.۱٪ / −۱.۳٪ | ۲.۰٪ / ۱.۴٪ | ۳ / ۲ |
| مرجع: همان منطق روی USDTTMN (در حساب چالش بسته) | +۵.۰٪ | ۳.۹٪ | ۴ |
| بازگشت به میانگین (رد شده) | −۲.۳٪ | ۲.۳٪ | ۹ |

**اجرای زنده:** از ۲۳ اکتبر ۱۰:۱۷ تهران روی لیارا؛ لاگ کامل در `logs/decisions/live_*.jsonl` (تحویل در پایان). خوانش صادقانه: بازده به ادامه‌ی ضعف تومان در ۷۲ ساعت وابسته است؛ سیستم برای گرفتن آن با ریسک محدود و شفافیت کامل ساخته شده، نه برای تضمین سود.

## ۶. اجرای مجدد (برای داوران)

```bash
git clone <repo> && cd Wallex
python -m venv .venv && source .venv/bin/activate          # Python 3.11+
pip install -r requirements.txt && pip install -e .
cp .env.example .env                                        # کلیدها را پر کنید (هرگز کامیت نمی‌شود)

pytest -q                                                   # ۲۰ تست
wallex-agent check                                          # والکس، حساب، گیت‌وی AI
wallex-agent fetch-data --days 30                           # کندل‌های ساعتی واقعی
wallex-agent backtest --ai off --symbols XAUTTMN            # قطعی
wallex-agent backtest --ai replay --symbols XAUTTMN         # بازپخش دقیق تصمیم‌های AI
wallex-agent run --mode shadow                              # بازار واقعی بدون سفارش
wallex-agent serve --mode live                              # ایجنت + داشبورد (http://localhost:8000)
wallex-agent report                                         # خلاصه‌ی لاگ تصمیم
```

**داکر / لیارا:** `docker compose up -d` یا دیپلوی ZIP روی لیارا (`liara.json`، دیسک `data` روی `/app/data`، متغیرها از `.env.example`). داشبورد: `https://<app>.liara.run/?token=...`.

**MCP برای Claude:** `claude mcp add --transport http wallex-agent "https://<app>.liara.run/mcp?token=..."` یا کانکتور سفارشی در claude.ai. ابزارها فقط‌خواندنی‌اند: `get_status`، `get_positions`، `get_markets`، `get_regimes`، `get_decisions`، `get_trades`، `get_risk_limits`، `get_equity_curve`، `get_strategy_description`.

## ۷. لاگ تصمیم (تحویلی)

`logs/decisions/<mode>_<run>.jsonl`، یک JSON در هر خط:

| kind | محتوا |
|---|---|
| `cycle` | هر دقیقه: رژیم با همه‌ی اعداد، وضعیت هر حامل (وزن، سقف، کف، گارد)، روایت هر نماد (چرا اقدام شد / نشد)، اقدام‌ها |
| `regime` | خروجی تحلیل رژیم AI با اطمینان و توضیح |
| `entry` / `top_up` | سیگنال، رژیم، تصمیم AI و دلیل، طرح ریسک، equity قبل از ورود، fill واقعی |
| `rebalance` | فروش جزئی برای بازگشت به وزن هدف، با PnL |
| `exit` | دلیل خروج، PnL تومانی و درصدی، مدت نگهداری |
| `reject` / `ai_overruled` / `no_entry` / `hold` / `reconcile` / `kill_switch` / `error` | بقیه‌ی تصمیم‌ها و رویدادهای ایمنی |

هر سفارش فقط از `Agent.step()` عبور می‌کند؛ معامله‌ای که رکورد نداشته باشد وجود ندارد. هش کامیت در `run_start` ثبت می‌شود.
